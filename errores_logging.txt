
¿QUÉ ES UN PIPELINE EN DATA SCIENCE?
Es una cadena de procesos automatizados que transforma datos crudos → información lista para análisis o modelos.

ESTRUCTURA TÍPICA DE UN PIPELINE
DATOS CRUDOS → LIMPIEZA → TRANSFORMACIÓN → ANÁLISIS → REPORTE/MODELO
   (CSV)       (filtros)   (agregaciones)   (EDA)      (insights)

EJEMPLO CONCRETO
# Pipeline de clientes
1. Leer CSV raw/clientes.csv
2. Filtrar activos y con contrato > $1000
3. Calcular métricas (edad promedio, top ciudades)
4. Guardar reporte en processed/clientes_filtrados.csv
5. Enviar alerta si hay < 100 registros
Registrar QUÉ pasó, CUÁNDO y POR QUÉ en cada etapa del proceso.

¿QUÉ SE LOGUEA?
Todo lo que pasa y manejando los errores con mensajes claros.

Nivel                         Cuándo usarlo                                         Ejemplo
DEBUG                         Detalles internos, solo para desarrollo       "Chunk 4: 500 filas procesadas"
INFO                          Pasos normales del proceso                    "Cargados 10,000 registros"
WARNING                       Algo raro, pero el proceso sigue              "Columna 'city' tiene 50% nulos"
ERROR                         Algo falló, puede continuar                   "No se pudo calcular métrica X"
CRITICAL                      Fallo grave, hay que detener todo             "Base de datos caída, deteniendo"

Las haremos clases que hereden de exception, para pasar el mensaje de error descriptivo.
class PipelineError(Exception): ... Personalizada, NO de PY.
class ArchivoNoEncontradoError(PipelineError): ...
class DatosInvalidosError(PipelineError): ...
class ColumnaFaltanteError(PipelineError): ...

Entonces las clases hijas heredan de PipelineError, que a su vez hereda de Exception. 
Creas tu propia jerarquía de errores.
Exception                        ← clase base de Python
    └── PipelineError            ← tu clase base personal (vacía, solo agrupa)
            ├── ArchivoNoEncontradoError
            ├── DatosInvalidosError
            ├── ColumnaFaltanteError
            └── TipoIncompatibleError

🎯 ¿POR QUÉ CREAR EXCEPCIONES PROPIAS?
Beneficio	                  Ejemplo
Semántica clara	         raise ArchivoNoEncontradoError('mensaje') vs raise Exception('mensaje')
Captura selectiva	         except ColumnaFaltanteError e: acceso a "e"
Mensajes específicos	      TipoIncompatibleError(columna="edad", ...)

🎯 DIFERENCIA CLAVE ENTRE: raise Vs. except
Concepto	      Qué hace	                   Cuándo usar
raise	         LANZA una excepción	       Cuando detectas un error y quieres notificarlo
except	      CAPTURA una excepción	    Cuando quieres manejar un error y recuperarte o loguearlo

class PipelineError(Exception): # Esta excepción es personalizada, NO de PY.
    """Clase base para todos los errores del pipeline. 
    Agrupa las 4 excepciones hijas bajo un nombre común,
    permitiendo capturarlas todas con un solo except."""
    pass

class ArchivoNoEncontradoError(PipelineError):
    """
    El archivo de entrada no existe en la ruta especificada.
    Nivel de log sugerido: ERROR
    """
    pass

class DatosInvalidosError(PipelineError):
    """
    El archivo existe pero sus datos no son utilizables.
    Ejemplo: CSV vacío, archivo corrupto.
    Nivel de log sugerido: ERROR
    """
    pass

class ColumnaFaltanteError(PipelineError):
    """
    El DataFrame no contiene una columna requerida para la operación.
    Nivel de log sugerido: ERROR
    """
    pass

class TipoIncompatibleError(PipelineError):
    """Se intentó una operación con un tipo de dato incorrecto.

    Ocurre cuando:
    - Se compara una columna string con un número → df['city'] > 40
    - Se aplica una operación matemática a texto  → df['nombre'] * 2
    - El origen de datos cambió el tipo de columna sin aviso

    A diferencia de las otras excepciones, esta está desarrollada
    con atributos propios para que el log pueda registrar información
    estructurada: qué columna falló, qué tipo tenía y qué se esperaba.
    Esto permite diagnósticos más precisos sin abrir el CSV.

    Atributos:
        columna       : nombre de la columna con el problema
        tipo_real     : dtype que tiene la columna en el DataFrame
        tipo_esperado : dtype que el pipeline necesitaba"""
    
    #? 1. Constructor personalizado
    #* al lanzar esta exception, le pasamos como argumento los datos 
    #* necesarios par construir el mensaje descriptivo → str(e)
    def __init__(self, columna: str, tipo_real: str, tipo_esperado: str):
        self.columna       = columna
        self.tipo_real     = tipo_real
        self.tipo_esperado = tipo_esperado

        #? 2.  Construimos e mensaje descriptivo de esta excepcion con los atributos 
        mensaje = (
            f"Columna '{columna}' tiene tipo '{tipo_real}', "
            f"se esperaba '{tipo_esperado}'.\n"
            f"¿Cambió el origen de datos? Verifica el CSV de entrada."
        )
        #? 3. pasa el mensaje a Exception para que str() funcione
        super().__init__(mensaje)
